# ArcForge 0.4.2

ArcForge 0.4.2 is a reference-corpus integrity release. The seventeen skills,
the routing layer, the four modes, and every behavioral contract are unchanged.
What changed is the quality of the deep material the skills hand an agent when
it goes one link past `SKILL.md`: the bundled reference papers.

## The problem this release fixes

An audit of all 294 paper artifacts (147 canonical papers plus 147 portable
skill copies) found that the implementation-intelligence layer — the section
meant to answer *what rule, what failure, what evidence* for each subtopic —
had been machine-assembled rather than written. Three defect classes:

1. **Cloned cells.** Sibling subtopics shared one byte-identical rule block, so
   a paper on cryptography said the same thing about hashing, encryption, and
   key rotation. The worst papers were 80–91% duplicated text.
2. **False authority.** Placeholder bullets carried MUST/SHOULD grades with no
   content behind them, and 169 invariant blocks promised topic-specific
   invariants while delivering template filler.
3. **Wrong-domain paste at normative grade.** The cryptography paper graded
   "define metric type and label allowlists" as a MUST under asymmetric
   encryption. Queue-ordering sections taught API pagination. Network
   partitions taught shard-key selection. Cache-expiry boilerplate appeared in
   the TLS, time-handling, lifecycle, idempotency, quota, batch-processing,
   temporary-data, randomness, M2M-authentication, API-keys, and AI-memory
   papers.

An agent following these papers verbatim would have implemented the wrong
property while citing authoritative-looking sources.

## What changed

- Thirty canonical papers were rewritten in their intelligence sections, each
  subtopic now carrying a specific rule, its production failure mode, and the
  codebase evidence to inspect — together with their owning skill copies so
  semantic parity holds. Highlights: current cryptographic guidance (OWASP
  Argon2id floors, NIST SP 800-63B-4 verifier policy, SP 800-38D nonce bounds),
  TLS/PKI operations per RFC 9325/8996, workload-identity federation replacing
  static secrets, GDPR-grade pseudonymization/anonymization separation,
  ISO 4217 money arithmetic, CDC snapshot-to-log-position consistency,
  Postgres DDL lock mechanics (`lock_timeout`, concurrent index builds,
  NOT VALID→VALIDATE), retry jitter mathematics, circuit-breaker state
  machines, token-bucket rate-limiting math, distributed-lock fencing,
  outbox/CDC publishing mechanics, SPF/DKIM/DMARC email authentication,
  Kubernetes termination sequencing, RAG chunking/embedding/citation
  discipline, and load/stress/spike/soak/capacity test differentiation.
- Wrong-domain contamination was eliminated corpus-wide: every identified paste
  signature was either rewritten to domain-correct content or confirmed to sit
  in its legitimate home. Corpus-wide rule-block duplication fell from roughly
  two-thirds of sampled sections to 4.2%; zero papers retain a
  majority-duplicated intelligence section.
- Mechanical integrity: 169 false-authority invariant blocks removed, 120
  clipboard residue lines stripped from paper 147, one mislabeled citation
  title corrected, and both `manifest.json` (per-paper hashes and counts) and
  `MANIFEST.sha256` regenerated against shipped bytes.

## Compatibility

Nothing installed against 0.4.1 changes behavior. Skill IDs, frontmatter,
routing-map bytes, mode semantics, output contracts, and stop conditions are
untouched. All edits are reference-content corrections; no new execution
authority was introduced.

## Not verified

The behavioral evaluation suite was not re-run for this release: the cases
exercise skill-level routing and gating, which did not change. Papers 016, 027,
010, 007, and 013 remain correct-but-repetitive and are queued for the same
rewrite depth in a future release.
